# CP Buy, UI Rework and Smaller Posts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** CraftProfit 1.2.0 adds the following:
- a CP Buy tab: cheapest per unit first, a "Buy cheapest" countdown, a materials list, and shift-click search;
- a readable, organized look inside the AH;
- CP Sell defaulting to 1 auction of 2.

**Architecture:**
- The 1.1.0 flip purchase machinery moves into a shared `Buyer` module keyed by row identity. Flip and CP Buy both buy through it, so `PlaceAuctionBid` keeps exactly one call site.
- A `Style` module holds the layout constants and widget helpers that every page uses.
- CP Buy is logic (`Buy.lua`) plus page (`BuyUI.lua`), like Sell/SellUI.

**Tech Stack:** WoW 3.3.5a Lua 5.1 addon. Tests: `lua5.1 tests/run.lua` with `tests/wow_mock.lua`; `lua5.1 tests/check_globals.lua`; `luac5.1 -p`.

**Spec:** `docs/superpowers/specs/2026-10-16-buy-and-ui-design.md`

## Global Constraints

- Lua 5.1 only. Don't use `C_Timer`, `BackdropTemplate` or `SetSize`; use SetWidth/SetHeight. `frame:SetBackdrop{...}` is native in 3.3.5.
- `PlaceAuctionBid` runs only synchronously inside a button OnClick. There is exactly one call site in the addon, in `Buyer.lua`. It buys only a "list" row matching item id, count, buyout and seller exactly.
- `StartAuction` has one call site (Sell.lua) and `CancelAuction` has one (Auctions.lua). Neither changes.
- Never read a "list" batch larger than 50 rows (a whole-AH getAll list).
- No ✓/⚠/emoji or other non-ASCII in game text. Icons only via `ns.Util.ICON_OK`, `ICON_WARN`, `ICON_GOLD` and the stock coin textures (`Interface\MoneyFrame\UI-GoldIcon`, `UI-SilverIcon`, `UI-CopperIcon`).
- Everything stays inside the AH. The page frame is AuctionFrame TOPLEFT (20,-72) to BOTTOMRIGHT (-10,40), i.e. 802 × 335.
- New globals are allowed only for frame names prefixed `CraftProfit`, our `AuctionFrameTab<n>` tabs, and `StaticPopupDialogs` keys `CRAFTPROFIT_*`.
- Every new WoW API name read goes in the `tests/check_globals.lua` allowlist.
- Toc order: Util, Style, Profit, Prices, Recipes, Scanner, Listings, Buyer, UI, ListingsUI, Tabs, Flip, Buy, BuyUI, Sell, SellUI, Auctions, AuctionsUI, Core.
- Test command: `lua5.1 tests/run.lua && lua5.1 tests/check_globals.lua` must exit 0.
- Sell default counts: stack = min(2, maxStack, owned), stacks = 1.
- Buy pick rule: among buyable rows (not mine, buyout > 0, not bought), take those with count ≤ remaining need and pick the cheapest unit. If none fits, pick the lowest stack total (buyout). With no need set, pick the cheapest unit.
- Commit messages end with the attribution lines from your own session's attribution reminder. If you have none, use `Co-Authored-By: Claude <noreply@anthropic.com>` and `Claude-Session: https://claude.ai/code/session_01NsBkFAYLu7eq5qAR7jw8sR`.

## Review Focus

1. A bought row is still in the cache before the post-buy check refreshes it. The next "Buy cheapest" must pick a different row (Task 6 `bought_row_skipped_until_refresh`).
2. The need is 4 and only stacks bigger than 4 exist. Pick the lowest stack total, never a pricier one (Task 6 `nothing_fits_takes_lowest_total`).
3. The cheapest row is the player's own or an alt's. It is never picked or bought (Task 6 `own_rows_never_picked`).
4. The AH name search matches substrings: "Frostweave" returns cloth, bolts and bags. CP Buy shows and buys only the item the player meant, i.e. the exact (case-insensitive) name match (Task 6 `substring_results_keep_only_the_named_item`).
5. Shift-clicking a reagent while the chat box is open sends the link to chat and runs no search. Shift-clicking with another page shown does nothing (Task 7 `shift_click_only_on_buy_page_without_chat`).

### Task 6: CP Buy logic

**Files:**
- Create: `CraftProfit/Buy.lua` (toc after Flip)
- Test: `tests/test_buy.lua`

**Interfaces:**
- Consumes:
  - `Scanner.PriceCheck({id, name})`, `Scanner.LoadPage(name, 0)`, `Scanner.IsBusy()`, SCAN_FINISHED;
  - `Listings.Get(id)` (rows sorted by unit; fields `unit, count, buyout, seller, mine, outlier`);
  - `Buyer.Buy/State/IsBought` (Task 1);
  - `Recipes.Get(id)` (`{name, made, reagents={{id,name,count}}}`), `Recipes.TrackedIDs()`, `Recipes.Depth(id)`;
  - `GetItemCount`, `GetItemInfo`.
- Produces (`ns.Buy`):
  - `Buy.Search(text) -> ok, err`:
    - Trims the text and resolves the id with `GetItemInfo(text)`; the link's id is used when it's cached.
    - If the item isn't cached: `LoadPage(text, 0)` and state "resolving". On the next `Buy.OnListUpdate()`, the first row whose name equals the text case-insensitively gives the id, then `PriceCheck`. No match gives status `"No item called <text> on the Auction House."`.
    - If the scanner is busy: queue the search and run it on SCAN_FINISHED. The status is "Waiting for the current scan...".
  - `Buy.SearchLink(link)`: id and name come from the link, then `PriceCheck` runs directly.
  - `Buy.Current() -> id, name`.
  - `Buy.Rows() -> rows` for the current id (Listings.Get).
  - `Buy.SetNeed(n)`: nil or ≤0 clears it; it resets the bought counter.
  - `Buy.Need() -> remaining or nil`.
  - `Buy.Pick() -> row or nil`: the Global Constraints rule. Bought rows (`Buyer.IsBought`) and `row.mine` rows are never picked.
  - `Buy.BuyCheapest() -> ok, msg`: `Buyer.Buy(id, Buy.Pick(), name)`. Call it only from OnClick.
  - `Buy.BuyRow(row) -> ok, msg`: refuses mine or bought rows with "That's your own listing." / "Already bought". Call it only from OnClick.
  - On `BUYER_CHANGED(id,row)` with state "bought" for the current id, it adds `row.count` to bought and `row.buyout` to spent, and lowers the remaining need.
  - `Buy.Status() -> text`:
    - `"Bought N of M (spent X)"` while a need is set;
    - `"Done (bought N)"` when remaining ≤ 0;
    - otherwise the last message.
  - `Buy.Materials(recipeId, crafts) -> list` of `{id, name, need, have}`:
    - "ready" depth: direct reagents × crafts.
    - "scratch" depth: a reagent that has a known recipe is replaced by its own reagents × (count / made). Recurse, with a visiting set against loops.
    - Equal ids are merged, need is rounded up (`math.ceil`), and `have = GetItemCount(id)`.
  - `Buy.OnListUpdate()` is routed by Core.
  - Fires `BUY_CHANGED`.
