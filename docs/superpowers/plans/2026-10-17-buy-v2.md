# CP Buy v2, Tooltip Prices, Fresh Window and Post Sizes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** CraftProfit 1.3.0 adds the following:
- CP Buy works like Auctionator: full-width results, item and list views, grouped listings, shopping lists;
- AH prices and craft cost on item tooltips;
- no rescans inside a 3-minute fresh window;
- CP Sell remembers post sizes per item, with a default the player sets.

**Architecture:**
- `Prices` owns the fresh window. `Scanner` gains a multi-item name search (`Scanner.Search`) and an opt-in fresh skip for targeted scans.
- `Listings.Group` merges identical rows. A new `Lists` module holds shopping lists, and a new `Tooltip` module adds lines to the game's tooltips.
- `Buy`/`BuyUI` are rebuilt around three views on one generic full-width table, which `ListingsUI` now provides.
- `Sell` stores post sizes in `db.sell`.

**Tech Stack:** WoW 3.3.5a Lua 5.1 addon. Tests: `lua5.1 tests/run.lua` with `tests/wow_mock.lua`; `lua5.1 tests/check_globals.lua`; `luac5.1 -p`.

**Spec:** `docs/superpowers/specs/2026-10-17-buy-v2-design.md`

## Global Constraints

- Lua 5.1 only. Don't use `C_Timer`, `BackdropTemplate` or `SetSize`; use SetWidth/SetHeight.
- `PlaceAuctionBid` has exactly one call site (Buyer.lua). `StartAuction` has one (Sell.lua) and `CancelAuction` has one (Auctions.lua).
- A purchase starts only synchronously inside a button OnClick. `Buyer.Buy` is called from exactly two places: `Flip.Buy`, and one local `buyRow(row)` in Buy.lua that `Buy.BuyCheapest` and `Buy.BuyGroup` (and, until Task 8, `Buy.BuyRow`) share.
- Never buy the player's own or an alt's listing (`row.mine`). Keep the exact row match and the stale-index skip, and search again when a listing is gone (BUYER_LOST).
- Never read a "list" batch larger than 50 rows.
- Game text is ASCII only. Icons only via `ns.Util.ICON_*` and `ns.Style.Money` coin textures.
- Everything stays inside the AH page frame, 802 × 335 (`Style.PAGE_W`, `Style.PAGE_H`).
- New globals are allowed only for frame names prefixed `CraftProfit` and `StaticPopupDialogs` keys `CRAFTPROFIT_*`. Every new WoW API name read goes in the `tests/check_globals.lua` allowlist.
- Toc order after this plan: Util, Style, Profit, Prices, Recipes, Scanner, Listings, Lists, Tooltip, Buyer, UI, ListingsUI, Tabs, Flip, Buy, BuyUI, Sell, SellUI, Auctions, AuctionsUI, Core.
- Fresh window: `db.freshSeconds`, default 180. `/cp fresh <minutes>` takes 0-60; 0 means always rescan.
- Search cap: 20 pages (1000 listings). Past it the status says "Showing the first 1000 listings - type more of the name."
- Post sizes: the default is 2 × 1. Stack is at most 1000 and auctions at most 100, both whole numbers ≥ 1.
- Test command: `lua5.1 tests/run.lua && lua5.1 tests/check_globals.lua` must exit 0 after every task.
- Commit messages end with the attribution lines from your session's attribution reminder. Never put a model name in a commit.

## Review Focus

1. **Rows from a name search buy the wrong page.** Their page numbers belong to the name search, but `Buyer.Buy` loads the category search's pages. The search never stores listings, so the item view always gets rows from a price check (Task 2 `search_stores_prices_not_listings`, Task 7 `item_after_search_price_checks`).
2. **A capped or early-stopped search leaves some items with only part of their listings.** That must not become the stored price or count as fresh (Task 2 `capped_search_stores_no_prices`).
3. **Buyer's after-purchase price check runs inside the fresh window.** It must not be skipped: only Scan tracked and Search all skip fresh items (Task 1 `price_check_ignores_fresh_window`).
4. **An item added to a list may not be in the client cache.** The list keeps the name it was added with, and Search all searches by it (Task 4 `own_list_keeps_names`).
5. **Deleting the list that is on screen.** The view leaves the deleted list, and nothing errors on the next draw (Task 8 `deleting_the_shown_list_leaves_it`).

### Task 2: Scanner.Search (every item of a name search)

**Files:**
- Modify: `CraftProfit/Scanner.lua`
- Test: `tests/test_scanner.lua`

**Interfaces:**
- Consumes: `Listings.Normalize`, `Listings.MineSet`, `Listings.Ratio`, `Prices.SetAH`.
- Produces:
  - `Scanner.Search(text, opts) -> ok, err`. err is "closed", "busy" or "empty" (blank text). `opts.stopOnExact`: end at the first page that has an item whose name equals `text` (case-insensitive).
  - The search runs in the same state machine as targeted scans (`job.search = true`, `job.text`, `job.page`):
    - it sends a name-only query (no category);
    - it waits for item links (not seller names);
    - it keeps the late-page fingerprint check, the timeout retry and the OnQuery resend.
  - It fires `SEARCH_DONE(text, results, capped, exactId)`, then `PRICES_CHANGED`, then `SCAN_FINISHED`.
    - `results` is sorted by name: `{ id, name, texture, unit, auctions, quantity, t }`.
      - `unit`: the cheapest priced, non-outlier unit of `Listings.Normalize(raw, MineSet(), Ratio())`, or nil.
      - `auctions`: the number of listings. `quantity`: the sum of their counts. `t`: `ns.Now()`.
    - `capped`: page 20 was reached and more pages exist.
    - `exactId`: the id when stopOnExact ended the search, else nil.
  - Only a search that read every page (`not capped and not exactId`) calls `Prices.SetAH(id, unit, pricedCount, now)` for each item. No search calls `Listings.Store`.
  - Status lines:
    - `'Searching "<text>": page <p>'` while running;
    - `'Search done: <n> items'`;
    - the cap text from Global Constraints;
    - `'No items called "<text>" on the Auction House.'` for none;
    - on Stop, `'Search stopped (<reason>)'`.
  - The timeout skip message and `Stop` use `job.text` when `job.search` is set.
  - Factor the cheapest-unit loop out of `finishItem` into a local `bestUnit(rows)` that both use.
