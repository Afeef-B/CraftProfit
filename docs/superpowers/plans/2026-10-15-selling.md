# CraftProfit Selling Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add "CP Sell" and "CP Auctions" Auction House tabs (undercut posting with crafting profit, own-auction undercut view and cancelling) and per-recipe Ready-made / From-scratch craft depth to CraftProfit.

**Architecture:** New pure module `Listings` holds price-check rows and the undercut maths; the existing `Scanner` gains a collect mode feeding it. `Tabs` adds two AH tabs whose pages are built by `SellUI` and `AuctionsUI`, each driven by a logic module (`Sell`, `Auctions`) that the tests exercise through the mock WoW API. Modules talk through the existing `ns.On`/`ns.Fire` bus.

**Tech Stack:** Lua 5.1 (WoW 3.3.5a, interface 30300), FrameXML 3.3.5 templates; tests: `lua5.1 tests/run.lua` with `tests/wow_mock.lua`.

**Spec:** `docs/superpowers/specs/2026-10-15-selling-design.md` (builds on `2026-10-15-craftprofit-design.md`)

## Global Constraints

- Lua 5.1 only; no `C_Timer`, no `BackdropTemplate`, no `SetSize` reliance (use `SetWidth`/`SetHeight`).
- Every `StartAuction` / `CancelAuction` call happens synchronously inside a button `OnClick` (or a StaticPopup `OnAccept`); never from `OnUpdate` or events.
- Undercut: cheapest non-mistake other seller `L` → `L > 100` ? `floor((L-1)/100)*100` : `max(1, L-1)`; never undercut your own or your alts' auctions (match the lowest of yours).
- Mistake listings: other-seller rows (with buyout, sorted) — largest `i <= 3` with `unit[i] < ratio * unit[i+1]` marks rows `1..i` `outlier`; `ratio = CraftProfitDB.outlierRatio or 0.5`.
- No ✓/⚠/emoji characters in game text (3.3.5 fonts lack them). Icons: `|TInterface\RaidFrame\ReadyCheck-Ready:14|t`, `|TInterface\DialogFrame\UI-Dialog-Icon-AlertNew:14|t`, `|TInterface\MoneyFrame\UI-GoldIcon:14|t` (constants `ns.Util.ICON_OK`, `ICON_WARN`, `ICON_GOLD`, added in Task 2).
- `PlaceAuctionBid` only inside a button `OnClick`, only for a "list" row matching item id, count, buyout and seller exactly.
- Starting bid = buyout. `StartAuction(unit*stack, unit*stack, duration, stack, stacks)`; durations 1/2/3 = 12/24/48 h, default 2.
- Tab buttons from `AuctionTabTemplate`, anchored `TOPLEFT` to the previous tab's `TOPRIGHT`, x −8.
- Listings cache reuse window: 60 s.
- New globals allowed: frame names prefixed `CraftProfit`, `AuctionFrameTab<n>` for our two tabs, `StaticPopupDialogs` keys prefixed `CRAFTPROFIT_`.
- Toc order: Util, Profit, Prices, Recipes, Scanner, Listings, UI, ListingsUI, Tabs, Flip, Sell, SellUI, Auctions, AuctionsUI, Core.
- Test command: `lua5.1 tests/run.lua && lua5.1 tests/check_globals.lua` (exit 0).

## Review Focus

1. A price check finishes after the player already typed a price → the typed price stays → Task 7 test `typed_price_survives_price_check`.
2. Player swaps the item in CP Sell while the old item's price check is running → old results never price the new item → Task 7 test `stale_price_check_ignored`.
3. Stack × stacks larger than what's in the bags → Post disabled with a reason → Task 7 test `post_disabled_cases`.
4. The owner list reorders after each cancel → the next cancel re-finds the right index, never cancels a sold or wrong auction → Task 9 test `cancel_uses_fresh_index`.
5. A recipe that makes 2 per craft → cost per item = recipe cost / made in the Sell profit line → Task 7 test `profit_line_uses_cost_per_item`.
6. The flip listing changed or sold before the click (same seller relists at another price) → nothing is bought → Task 6 test `buy_requires_exact_match`.

  - `Store(id, rows)` → `cache[id] = { t = ns.Now(), rows = rows }`, fires `"LISTINGS_UPDATED", id`; `Get(id) -> rows|nil, age|nil`.
